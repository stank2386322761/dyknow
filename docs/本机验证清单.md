# DyKnow 3.1 本机验证清单（第二轮，交给 GPT / Codex 执行）

> 给执行的 AI：按顺序执行，**不要修改任何代码**。把每一步的 `RESULT:` 行、所有带 ❌ / ⚠️ 的行原样记下来，最后汇总给用户。
> 退出码：0 全部成功；4 = 跑完了但有条目失败或中断（不是全部成功）；2 = 需要扫码；3 = 抖音/浏览器问题。
> 这一轮重点复查上一轮的 3 个问题：转录全部报 IndexError、`--limit` 第二次还有新条目、搜索卡住。

## 0. 安装新版本

新建一个目录，不要覆盖旧的 dyknow-v3：

```powershell
# 把 dyknow-v3.1.zip 解压到一个新目录，进入解压出来的 dyknow-v3.1 文件夹
python -m venv .venv
.venv\Scripts\activate
pip install -e .[gpu] -i https://pypi.tuna.tsinghua.edu.cn/simple
python -m unittest discover -s tests
```

预期：最后一行是 `OK`（共 51 个测试）。

登录状态和模型保存在用户数据目录，和上一轮共用，**不需要重新扫码**。

## 1. 环境检查

```powershell
dyknow doctor --skip-gpu-test
```

预期：「✅ ffmpeg 可用」「✅ 抖音已登录」「✅ 收藏接口可以直接读取」。

## 2. 复查：上一轮失败的 12 条重新转录

```powershell
dyknow config output_dir "<上一轮的新知识库目录>"
dyknow transcribe --retry-failed
```

预期：上一轮那 12 条大部分变成 ✅，不再出现 `IndexError`。如果还有失败，记下 ❌ 后面的原因原文。
同时记录每条后面显示的秒数。

## 3. 复查：--limit 的含义

```powershell
dyknow update --limit 5
dyknow update --limit 5
```

预期：第二次显示「检查了最新 5 条，其中新的 0 条」，RESULT 里 `new` 为 0。

## 4. 复查：搜索

```powershell
dyknow search AI编程 --limit 3
```

预期：3 分钟内结束并有 RESULT。如果超过 3 分钟没结束，按 Ctrl+C 停止，并把屏幕上「打开页面」「滚动第 N 轮」这些进度行原样记下来（这些就是这次新加的、用来判断卡在哪一步的日志）。

## 5. 新功能：画面截图

```powershell
dyknow frames --limit 3
dyknow config frames 8
dyknow link "<任意一条从抖音 App 复制的分享文案（用短链接那种）>"
```

预期：
- 第一条命令给 3 条已有笔记补上截图
- 最后一条命令新建的笔记里有折叠的「画面」区块
- 笔记旁边的 `附件\<视频ID>\` 文件夹里有 jpg 图片
- 在 Obsidian 里展开「画面」能看到图片

把 link 生成的笔记全文复制给用户，并说明 Obsidian 里截图能不能正常显示。

## 6. 汇总给用户

1. 每一步的 RESULT 行，以及所有 ❌ / ⚠️ 行
2. 第 2 步：成功几条、失败几条，每条耗时
3. 第 4 步：用了多久，是否结束
4. 第 5 步：笔记全文，截图在 Obsidian 里是否正常显示
5. 如果有报错，附上 `%LOCALAPPDATA%\dyknow\logs\dyknow.log` 的最后 100 行
