# DyKnow 3.2 本机验证清单（交给 GPT / Codex 执行）

> 给执行的 AI：按顺序执行，**不要修改任何代码**。把每一步的 `RESULT:` 行、所有带 ❌ / ⚠️ 的行原样记下来，最后汇总给用户。
> 退出码：0 全部成功；4 = 跑完了但有失败；2 = 需要扫码；3 = 网站或浏览器问题。
> 需要扫码的步骤，停下来请用户本人操作。

## 0. 安装

新建一个目录，不要覆盖旧版本：

```powershell
# 把 dyknow-v3.2.zip 解压，进入 dyknow-v3.2 文件夹
python -m venv .venv
.venv\Scripts\activate
pip install -e .[gpu] -i https://pypi.tuna.tsinghua.edu.cn/simple
python -m unittest discover -s tests
```

预期：最后一行 `OK`（共 62 个测试）。抖音登录状态和模型和之前共用，不用重新扫码。

## 第一部分：复查上一轮的问题

```powershell
dyknow doctor --skip-gpu-test
dyknow config output_dir "<上一轮的新知识库目录>"
dyknow transcribe --retry-failed
dyknow update --limit 5
dyknow update --limit 5
dyknow search AI编程 --limit 3
```

预期：
- doctor 显示「✅ ffmpeg 可用」
- 上一轮失败的 12 条大部分变成 ✅，不再出现 IndexError（记录每条秒数）
- 第二次 `update --limit 5` 显示「检查了最新 5 条，其中新的 0 条」
- search 3 分钟内结束；超时就 Ctrl+C，并记下「打开页面」「滚动第 N 轮」这些进度行

## 第二部分：画面截图

```powershell
dyknow frames --limit 3
```

预期：3 条笔记多了「画面」区块，旁边 `附件\<视频ID>\` 里有图片，Obsidian 里能显示。

## 第三部分：找选题（新功能）

### 1. 登录小红书和知乎（用户本人扫码）

```powershell
dyknow login --site xhs
dyknow login --site zhihu
dyknow config niche "AI 工具实测和自媒体变现"
```

### 2. 热榜

```powershell
dyknow hot
```

记录 RESULT 里 `platforms`（每个平台几条）和 `errors`。打开 RESULT 里 `report` 指向的文件，把全文复制给用户。

### 3. 找对标

```powershell
dyknow find AI编程 --days 30 --limit 10
```

记录每个平台拿到几条、哪些平台 ❌ 及原因。打开报告，检查：
- 每个平台的表格是不是按点赞从高到低
- 发布日期是不是都在 30 天内（`?` 表示拿不到日期）
- 标题、作者、点赞数和网页上看到的是否一致（每个平台随便点开 1 条对比）

### 4. 存成笔记

```powershell
dyknow find AI编程 --days 30 --limit 5 --save 2
```

预期：在 `对标\AI编程\` 下面新建约 8 条笔记。打开一条小红书笔记和一条知乎笔记，检查「原文」里有没有正文、小红书有没有图片。

### 5. 原始数据（很重要）

第 2、3 步的 RESULT 里都有 `raw_dir`。**把这两个文件夹打包发给用户**（里面是网站返回的原始数据，开发者用它核对各平台的数据结构）。

## 汇总给用户

1. 每一步的 RESULT 行、所有 ❌ / ⚠️ 行
2. 第一部分：重新转录成功几条、失败几条、每条耗时；search 用了多久
3. 热榜报告全文、对标报告全文
4. 一条小红书笔记、一条知乎笔记的全文
5. 两个 raw_dir 文件夹的压缩包
6. 如果有报错，附上 `%LOCALAPPDATA%\dyknow\logs\dyknow.log` 的最后 100 行
