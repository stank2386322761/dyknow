# 收藏同步流程检查与优化

检查日期：2026-10-03。

## 当前默认流程

检查登录 → 同步收藏并记录新增 ID → 只转录新增 → 更新每个视频的 MD → 报告清单、结果和位置 → 交给其他 AI 整理。
不自动摘要、归档或重建索引。默认检查最近 200 条，不能声称覆盖所有收藏。

## 已落实

- Git 工作树默认共用主项目 `data/`，环境变量可显式覆盖；模型默认路径也跟随实际数据目录，笔记目录继续读取持久化配置。
- `login` 复用已有 Cookie，不打开浏览器；`login --force` 用于强制扫码或换账号。
- 收藏抓取无 Cookie 时在同一浏览器会话内登录并继续抓取，不先启动另一套登录流程。明确跳转登录页时允许一次重登录；空数据不等同于登录失效，不循环扫码。
- 全量同步用 UPSERT 更新数据库元数据，保留状态、路径、转录 hash 和整理结果；不重新生成已有 MD。
- 相同视频即使改标题或归档，也复用已有 MD。重转录仅修改转写章节及相关状态，保留摘要、金句、自定义字段；旧摘要与新转写不一致时标记 needs_review，空结果保留旧转写。
- 文件缺失、读取失败或转录写入失败都不能标记成功，也不能删除可用于重试的音频。
- 本次新增范围独立记录到 `data/runs/`，支持 `transcribe --ids` 续跑，更新清单由数据库实际状态生成。
- 状态显示区分已保存 Cookie 与服务端有效性；AI 处理统计扫描真实笔记。
- 环境检测读取实际目录、音频工具与浏览器路径；分类树支持递归，归档支持按 ID 限定范围。

## 仍可优化

- 保存真正的开始时间及终态统计，当前进度文件可能落后一条。
- 明确区分接口拒绝、网络失败、无收藏和登录失效，避免依赖页面重定向判断。
- 迁移时检测失效的 Python、输出目录等配置。
- 测量转录吞吐，提供模型与线程配置，识别真实时长及无有效语音。

## 验证

回归覆盖工作树共享数据、登录不另开窗口、全量刷新保留归档内容及状态、重转录保留整理内容、写入失败不标记成功。全套 138 项通过，实际环境检查全部通过。线上抓取最近 3 条收藏成功，复用 Cookie 无需扫码；刷新 3 条实际已有记录后 MD 的 SHA-256、路径及处理状态完全一致。没有强制重新扫码，也没有转录本次验证发现的新收藏。
