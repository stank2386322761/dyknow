# 分类与 taxonomy 注册表

## 两个目录的语义

```text
未处理/     = 尚未完成 AI 知识处理
              （transcript_status 为 pending/done/failed，
                processing_status 为 pending）

待聚类/     = 已完成 AI 处理（processing_status: done），
              但当前没有足够稳定的分类归属，
              不应为了单条内容创建新分类
```

不要把「已处理但分类未定」的笔记放进 `未处理/`，也不要把「还没做摘要」的笔记放进 `待聚类/`。

旧版本可能已有 `未分类/`：程序读取时兼容（视为 `未处理/` 的等价入口），
但**不要**自动批量重命名或移动用户已有数据。需要迁移时使用显式命令：

```bash
python -m dyknow organize --migrate --dry-run   # 先看计划
python -m dyknow organize --migrate             # 执行迁移
```

## taxonomy 注册表

知识库根目录维护机器可读的分类注册表 `taxonomy.yaml`：

```yaml
version: 1
categories:
  - name: AI工具与开发
    aliases:
      - AI工具
      - AI开发
      - AI编程
    children:
      - name: Agent与工作流
        aliases:
          - Agent
          - AI Agent
      - name: 大模型与部署
        aliases:
          - 模型部署
          - 本地模型
```

- `name` 是目录名，也是笔记 `category` 字段应当填写的规范值。
- `aliases` 是该分类的同义词。措辞不同但语义相同的说法都应能映射回同一个 `name`。
- `children` 支持一层子分类，分类路径写作 `父类/子类`。

注册表由程序读写。模型只需要在笔记 frontmatter 写 `category`，
由 `organize` 命令解析到实际目录。

## 分类决策顺序（模型执行）

```text
1. 阅读内容，识别核心主题
2. 查看现有 taxonomy（不要凭记忆猜）
3. 优先选择已有分类
4. 再考虑 aliases 对应的分类
5. 没有稳定归属时把 category 留空
6. 只有当相近主题累计达到至少 3 条时，才建议建立新分类
7. 单个文件只有一个主分类
```

**不要**因为措辞稍有不同就自行产生近义目录，例如同时存在：

```text
AI工具 / AI开发 / AI编程 / AI编程工具 / 开发工具
```

这类重复目录会让知识库失去结构。

新分类的创建要遵守阈值：内容不属于任何已有分类时，先留空 `category`（进入 `待聚类/`），
等同类内容累计到 3 条，再由程序注册分类并建目录。

## 分类粒度

- 每个目录至少 3 条内容才值得独立成类
- 少于 3 条的归入相近目录，或留在 `待聚类/`
- 一个分类超过 30 条时考虑拆分子分类

## 命名

- 2-6 个字，一眼能看出内容类型，例如 `股票与量化`、`创业与副业`、`AI工具`
- **看话题不看人**：按视频讲什么分类，不按作者身份或粉丝量分类
- 唯一归属：跨多主题的内容，选占比最大的核心话题

## 责任划分

- **模型**：判断内容主题 → 在 frontmatter 写 `category`
- **程序**：读取 taxonomy → 解析 aliases → 校验阈值 → 创建目录 → 安全移动文件

模型不直接创建目录，也不直接移动文件。

## 示例分类体系（实际使用时动态生成，不要照搬）

    02-大模型与部署/
04-商业与投资/
