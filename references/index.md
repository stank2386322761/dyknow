# 索引结构

索引**由程序全量重建**，模型不手工统计、不手工维护。

```bash
python -m dyknow index
```

## 为什么不要手工维护

收藏量会持续增长。手工统计条数、拼接链接、累加分类数量必然会漂移，
一旦漂移，索引就会与真实笔记不一致，反而降低知识库可用性。
程序从当前 Markdown 文件的 frontmatter 与摘要区块读取真实状态后整体重建，不存在增量偏差。

## 根索引结构

根索引文件位于知识库根目录，名为 `知识库索引.md`。

```markdown
# 知识库索引
> 最后更新：2026-09-26 | 已处理 128 | 待处理 7 | 待聚类 4

## 概览
| 分类 | 已处理 | 待处理 |
| --- | ---: | ---: |
| AI工具与开发 | 128 | 7 |

## AI工具与开发
- [[Claude Code 的 5 个技巧]] — 一句话总结……
- [[本地部署 Qwen]] — 一句话总结……
```

要点：

- 根索引**只放一句话总结**，不放大段要点，也不放多条金句。1000 条视频的完整摘要堆进一个文件是无法使用的。
- 每个条目带 Obsidian 双向链接，链接按真实相对路径生成。
- 链接基于文件当前位置，因此 `organize` 移动文件后重新执行 `index` 即可得到正确链接。

## 分类索引

分类内容较多时，为分类目录单独生成 `索引.md`，其中可以展示更多信息：

- 一句话总结
- 最多 3 条要点
- 最多 1 条金句

完整内容只保存在单条视频笔记里。

## 统计口径

```text
已处理   = processing_status: done
待处理   = processing_status: pending（含未转录）
待聚类   = 已处理但位于 待聚类/ 或 category 为空
```

索引生成器必须：

- 不把索引文件自身当作视频笔记统计
- 对坏 frontmatter 或异常笔记给出警告，但不因单个坏文件导致整体失败
- 每次重建后覆盖旧索引，而不是追加
